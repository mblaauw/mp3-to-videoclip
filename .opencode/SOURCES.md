## Pinned selection

Five still-production recipes are installed by default for the still-film workflow:

- `runware-run`, `runware-models`, `runware-prompting` — execution/model/prompt
  foundations.
- `photoreal-stills`, `character-consistency` — look and identity technique.

The upstream checkout contains many recipes; `animate-image` and
`cinematic-video` are **deselected** because this project produces stills, not
generated motion. `bootstrap_production.py` moves any installed copy of those two
recipes byte-for-byte to `backups/unused-motion-skills/` (outside skill
discovery, never edited or deleted) and records the moved paths in its report, so
a parent process can snapshot them. The project `permissions` in `opencode.json`
also deny them (project scope only, preserving global access for a future
decision). Selected recipes are only copied when missing, and an adapted local
copy is reported and refused rather than overwritten, so pinned bytes are
preserved. `--check` performs none of this: it is read-only and writes nothing.

Selected sources are installed locally into the ignored `.opencode/skills/`.
Project-original skills (`clip-music-director` plus the nine `clip-*` stage
skills) live in the same directory and are whitelisted in `.gitignore` so they
are distributed with the project. They ship in the repository and are never
generated by the bootstrap command, which only verifies that each one is present
and declares its own name. OpenCode discovers these folders automatically; the
global `runware` skill is not overwritten. The six production agents are defined
inline in `opencode.json`, not as `agent/*.md` files.
